# LLM como 2º avaliador — registro (declaração de uso de IA)

- Modelo: `deepseek-v4-pro` (API DeepSeek), via delegator MCP do Claude Code; temperatura 0,3; sem ferramentas.
- Entrada: o arquivo `pares.txt` (gerado por `scripts/analysis/validation_build.py`; as instruções de rotulagem estão no início), divididos em lotes de até ~180 mil caracteres (um item nunca é dividido; os 2 pares maiores foram cortados no fim do diff, e o humano vê o diff completo no HTML).
- System prompt: "Você é um avaliador cuidadoso de engenharia de software. Responda somente no formato pedido."
- `deepseek_v3/` e `llm_pares_v3.csv` (06/nov/2026): `deepseek-v4-pro`, temperatura 0,3, prompt `prompt_llm2_pares.md` (v3) nos 280 pares, via API direta (`scripts/analysis/llm_pares_v3.py`).
- Revisão de evidência da dona na RQ2 (**feita em 07/nov/2026**): Claude Opus 5.5 (`claude-opus-5-5`, subagentes do Claude Code), nos 128 pares que o humano marcou `outra_capacidade` em `rotulagem_pares_humano.csv`.
  - Material: `revisao_dono/material/lote_1..6.txt` = blocos de `p4_dono.py` (linhas alteradas ≤40 + até 5 candidatas) + a observação do humano (e a spec dona que ele indicou, quando indicou). Os revisores podiam ler o texto completo de qualquer spec do repositório (`specs_text.parquet`) e, alguns, o diff completo em `data/api_pr_diffs*/raw`.
  - Critério (instrução dada): `confirmada` só se uma spec de outra capacidade do repositório (viva ou de change, qualquer data) tem texto que descreve o comportamento mudado (requisitos/cenários sobre a funcionalidade/componente); nome compartilhado ou o PR ter tocado a spec não bastam; a indicação do humano não é evidência por si. Senão `sem_evidencia` → `omite`.
  - 6 lotes paralelos (rigor variou entre lotes) → **passada única de força** por um só revisor sobre as 115 confirmadas: `explicita` (107) | `componente` (8) | `insuficiente` (0) → sensibilidade (h). `material/forca.txt`.
  - Cegueira: proibidos de abrir `data/validation/llm/`, `rotulagem_*`, `gabarito_*`. Resultado: `revisao_dono/decisoes.csv` (115 confirmadas, 13 sem evidência), com coluna `humano_veta_omite` à espera do avaliador.
- A rotulagem humana final da RQ2 (`rotulagem_pares_humano.csv`) foi decidida 100% pelo avaliador (declaração de 07/nov). **Esclarecimento de 19/nov:** nas specs com texto em chinês (piloto e pares novos), o avaliador usou tradução automática só para ler o texto; o código estava em inglês e todo rótulo é decisão dele. No piloto, ele **não** viu rótulos de LLM.
- **Rotulagem preliminar do piloto por LLM (05/nov), não guardada:** antes do codebook v3, um LLM rotulou às cegas os 58 pares do piloto e marcou 7 de 56 julgáveis como decay (12,5%; `docs/problemas.md` #41). Esse valor é a premissa da simulação de poder (`scripts/analysis/p4_poder.py`, `Y_PILOTO`). Os rótulos e o modelo dessa rodada **não foram guardados** (saíram na limpeza do material descartado); por isso o 12,5% é uma premissa do desenho, não um número reproduzível. Os rótulos v3 do DeepSeek no mesmo piloto (`llm_pares_v3.csv`) dão 5/56.
- **Crítica do desenho por LLM:** o DeepSeek v4 Pro (e, em revisões, o Claude) foi usado como revisor crítico do método, sem acesso aos rótulos (`docs/metodo.md` §5c, 07/nov; revisões em `docs/problemas.md`). As decisões ficaram com o autor.
- O LLM nunca vê o rótulo humano. Na RQ2, o LLM v3 vê o texto da spec viva, a lista de arquivos do PR e o diff do código ligado (`prompt_llm2_pares.md`). O humano é o padrão-ouro; o LLM é só 2º avaliador.
- Ameaças: contaminação (specs públicas podem estar no treino), não determinismo, efeito do prompt.
